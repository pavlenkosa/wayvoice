# Release notes

Before proposing a release, copy `TEMPLATE.md` to `VERSION.md` and replace every placeholder with English, user-facing facts. Commit the notes with the version and changelog changes before creating a tag. The release validator requires all four substantive sections.

These pages describe public releases; internal audits and checkpoints do not belong here. Do not add notes for an old published release merely to bypass validation or republish its assets. The full technical history remains in [CHANGELOG](../CHANGELOG.md).
